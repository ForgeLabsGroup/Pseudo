# Decisions (ADRs, short)

- **ADR-001 TypeScript monorepo, source-only packages.** Packages export `.ts`; Next `transpilePackages`, API runs on `tsx`. No build step = faster hackathon iteration.
- **ADR-002 Persona = the user's own face.** Users upload selfies; images use them as references (Gemini Flash Image / gpt-image-1 edits). No other real person's likeness.
- **ADR-003 In-process jobs instead of Inngest (for now).** Render runs one API instance; `runInBackground` + `agent_runs` gives tracking/SSE, publishing queue is DB-backed with retries + idempotent claim. Deviation from spec to cut infra for a 5-hour build. Swap in Inngest functions behind the same job functions later. A restart kills running jobs, so `jobs/reaper.ts` fails runs idle for 15+ min (at startup and every 5 min) and resets what they left behind (content stuck generating, likeness stuck training, pending usage rows).
- **ADR-004 Single API service on Render (no separate worker).** Publishing worker runs inside the API process. Split into its own service when scaling.
- **ADR-005 OpenAI SDK against any OpenAI-compatible endpoint.** Lets us use Gemini's free tier for text with the same code. Structured output via JSON mode + Zod validation (portable across providers).
- **ADR-006 Image quality > free.** Likeness is the product. Default provider is Gemini (multi-reference edits); use the paid Pro image model ("Nano Banana Pro") for the demo, Flash (free) for dev. If likeness is still weak after testing, add a dedicated identity provider (fal.ai flux-pulid or a FLUX LoRA trained on the user's selfies) behind `generateImage`. Video = template (Remotion) for MVP; image-to-video animation of generated photos is a stretch.
- **ADR-010 Higgsfield for likeness + motion (pending a bake-off).** Built for AI influencers: Soul ID trains the user's likeness once per persona (`POST /api/personas/:id/character` → `personas.character_refs.higgsfield`), image generation uses it, and image-to-video animates each scene still into a real clip (`content_media.role = scene_clip`). The Remotion template plays clips when present, else animates stills. ElevenLabs voice + captions are layered on top. API is paid (funded balance) and async; every Higgsfield call sits behind `packages/ai/src/higgsfield.ts` so we can fall back to Gemini/mock by env.
- **ADR-011 Research = live step of the Content agent with a 24h cache.** Modular `SocialSource` (Apify now) + `VideoWatcher` (Gemini, TS port of claude-video's gemini engine: whole video incl. audio). Playbooks hold patterns only. Influencers are team-curated per archetype in `config/archetypes.json`.
- **ADR-012 Research watcher = vision model on frames + transcript; source videos kept in a private bucket.** Supersedes the Gemini watcher choice in ADR-011 (Gemini stays available as `RESEARCH_WATCHER=gemini`). Featherless-style OpenAI-compatible models take images, not video/audio, so `RESEARCH_WATCHER=vision` samples N frames with the bundled ffmpeg, optionally adds a Whisper transcript (`TRANSCRIBE_PROVIDER`), and makes one chat call. Videos are downloaded (Apify URL, else yt-dlp), stored in the private `research-videos` bucket (service-role only, signed URLs for viewing) because Instagram/TikTok CDN links expire, and so analyses can be re-run with another model without re-downloading. `packages/research` stays Supabase-free via a `VideoStore` interface.
- **ADR-007 Client-side auth in web.** Supabase JS session in browser, token sent to API; API verifies with `auth.getUser`. Simpler than SSR cookies for an all-client dashboard.
- **ADR-008 Public-read media bucket.** Unguessable paths, server-only writes; avoids signed-URL plumbing. Revisit for production.
- **ADR-009 Mock publishing is first-class.** Same interface/validation as live; demo never depends on platform approvals.
